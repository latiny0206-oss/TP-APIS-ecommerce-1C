## Descripción
Pantalla de error para rutas no encontradas o recursos que ya no existen. El usuario aterrizó en una URL inválida o intentó acceder a un producto/orden eliminado.

## Datos del backend

No consume endpoints. Se muestra cuando:
- La URL no corresponde a ninguna ruta del frontend
- Un `GET /api/productos/{id}` o `GET /api/ordenes/{id}` devuelve 404 (`ResourceNotFoundException`)
- La respuesta de error incluye: `{ timestamp, status: 404, error: "Not Found", message: "Producto con id 999 no encontrado" }`

## Flujo de navegación
- **Viene desde:** URL directa inválida, link roto, recurso eliminado
- **Puede ir a:** Home (botón CTA), Catálogo (botón secundario), página anterior (botón "Volver")
- **Trigger:** Error de routing o respuesta 404 del backend

## Componentes UI
- NavBar (simplificado, sin búsqueda)
- Ilustración temática de montaña con sendero perdido
- Código de error "404" en tipografía grande
- Mensaje principal y explicación
- PrimaryButton "Volver al inicio"
- SecondaryButton "Ver catálogo"
- Link "Volver atrás" (browser history back)

## Estados
- [ ] Default — error genérico 404 (ruta no encontrada)
- [ ] Recurso específico — "El producto que buscás ya no existe" (cuando viene de un 404 de API)

## Notas de UX
- El mensaje debe ser amable y con tono de marca (aventura/montaña): "Parece que te perdiste en el camino".
- No mostrar mensajes técnicos al usuario.
- El código "404" puede ser estilizado como un elemento visual grande, no solo texto.
